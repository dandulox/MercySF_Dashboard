Mercy SF Web-Dashboard

Ein Browser-Dashboard rund um die Mercy SF Shakes & Fidget-CLI — Übersicht, Steuerung, Live-Daten und Analysen für alle Accounts, ohne das Terminal-Menü. Läuft auf einem eigenen Server, voll mobiltauglich.

Node.js + Express Kein Build-Step AES-256 verschlüsselte Zugangsdaten AGPLv3
Zum Repository Installation ansehen ☕ Mercy SF unterstützen
⚠️ Experimentell, Nutzung auf eigenes Risiko. Dieses Dashboard befindet sich in aktiver Entwicklung und kann Fehler enthalten. Automatisiertes Spielen (Botting) verstößt in der Regel gegen die Nutzungsbedingungen von Shakes & Fidget — es besteht grundsätzlich das Risiko einer Account-Sperrung, unabhängig davon, ob die Automatisierung über dieses Dashboard oder direkt über die CLI läuft.

01Was ist das?

Alles läuft auf Basis der offiziellen Mercy SF-CLI — es wird nichts am Bot selbst verändert, nur ein komplettes Web-Interface drumherum gebaut. Zusätzlich holt das Dashboard über sf-api von the-marenga Live-Daten (Ausrüstung, Gilde, Taverne, Mail) direkt vom Spieleserver.

03Funktionen

Ein Überblick über alles, was das Dashboard mitbringt.

▦

Übersicht

Ein-/ausklappbare Karten (Zustand bleibt gespeichert): Accounts-Tabelle, Charakter-Stats, Ausrüstung, Taverne, Gilde, Mail, Activity-Log.

🗂

Account-Verwaltung

Einmal einloggen — alle Charaktere eines Logins werden automatisch über alle Server hinweg gefunden. Passwörter liegen AES-256-verschlüsselt auf der Platte. Start/Stop/Pause pro Account, Bulk-Aktionen pro Login.

⌨

Web-Terminal

Pro Account eine eigene Konsolen-Session im Browser (xterm.js), inklusive automatisiertem Login-Durchklicken bis zum laufenden Bot.

🛡

Live-Spieldaten

Ausrüstung, Gilde, Taverne und Mail direkt vom Spieleserver (read-only, lokaler Rust-Dienst). Abfrage-Intervall frei einstellbar (10 Min / 1×Std / 1×Tag).

📈

Analysen & Erträge

SQLite-gestützte Auswertung von EP/Gold/Ehre pro Tag, erkannte Kampf-Fenster, Zeitreihen-Charts für Level, Erfahrung, Gold, Pilze, Ehre, Rang.

⚙

Einstellungen & Vorlagen

Alle Bot-Konfig-Schalter direkt im Browser. Konfiguration als Vorlage speichern und auf andere Charaktere anwenden, oder aus einem Windows-App-Backup importieren.

🔔

Benachrichtigungen

Erkennt Fehler/Warnungen automatisch aus dem Log-Output — Glocke mit Badge und Toast-Popups.

🕶

Anonym-Modus

Charakternamen verpixeln, z. B. für Screenshots oder Streaming — ein Klick, sofort wirksam.

🔁

Auto-Wiederanlauf

Charaktere, die vor einem Neustart/Update aktiv liefen, starten danach automatisch wieder — zeitversetzt, damit nicht alle gleichzeitig einloggen.

📱

Mobil nutzbar

Vollständig responsives Layout — Navigation als Menü, Tabellen und Konsole passen sich der Bildschirmbreite an.

⟳

Auto-Update-Check

CLI und Dashboard zeigen permanent ihren Update-Status; ein Klick installiert automatisch (git pull + Neubau bzw. Binary-Austausch).

🔐

Zugangsschutz

Ein Dashboard-Zugang (Single-Admin) mit Setup-Assistent, 12-Wort-Wiederherstellungsschlüssel und Passwort-Änderung direkt im Interface.

04Installation

Auf einem frischen Debian/Ubuntu-Server, als root.

curl -fsSL https://raw.githubusercontent.com/dandulox/MercySF_Dashboard/main/install.sh | bash

  • Abhängigkeiten & Dienste

    Das Skript installiert Node.js, Rust/Cargo für die sf-api-Bridge, Build-Tools für native Module sowie die Mercy-SF-CLI, richtet ein selbstsigniertes TLS-Zertifikat ein und startet Dashboard sowie sf-api-Bridge als systemd-Dienste.

  • Erster Aufruf

    Danach ist das Dashboard unter https://<server-ip>:8080 erreichbar — eine Setup-Seite führt durch das Anlegen des einen Dashboard-Zugangs.

  • Updates

    Erneutes Ausführen des Skripts aktualisiert nur Code und Dependencies — vorhandene Account-Daten, Zertifikate und die installierte CLI-Version bleiben unangetastet.

Deinstallation

curl -fsSL https://raw.githubusercontent.com/dandulox/MercySF_Dashboard/main/install.sh | bash -s -- --uninstall

Entfernt alles: beide systemd-Dienste, den kompletten /opt/mercy-Ordner inkl. Dashboard-Code, Zertifikate, CLI-Binary, gespeicherte Bot-Zugangsdaten, Dashboard-Zugang und die Ertrags-Statistik-Datenbank. Kein Zwischenschritt, keine Rückfrage.

05Bekannte Einschränkungen

Die CLI bietet keine offizielle Fernsteuerungs-API — sie ist als reines Text-Menü für interaktive Terminal-Nutzung gebaut. Alle Login-/Bot-Automatisierung basiert auf Pattern-Matching des Terminal-Outputs. Ändert sich der Wortlaut eines CLI-Menüs, kann die Automatisierung brechen, bis der Code angepasst wird.

  • Kein natives Pause-Kommando — "Pause" schaltet stattdessen alle aktiven auto_*-Konfig-Schalter aus.
  • Der Linux-Build der CLI schreibt keine logs/- oder battle_history/-Dateien — das Dashboard nutzt einen In-Memory-Ringpuffer aus dem Live-Terminal-Output.
  • Keine offizielle Versions-API für die CLI — der Update-Check vergleicht MD5-Hashes gegen die öffentliche Download-Datei.
  • Ein Dashboard-Selbst-Update unterbricht kurz die Verbindung, während sich beide systemd-Dienste neu starten.
  • sf-api liefert keine lesbaren Item-Namen (nur numerische IDs) — die Ausrüstungs-Anzeige zeigt Slot, Typ, Attribute und Qualität, keine Klarnamen.
  • Die täglichen Gold-Erträge sind eine Netto-Veränderung pro Zeitfenster (kann Ausgaben enthalten) — EP und Ehre sind exakt.
  • Kein Rate-Limiting auf Login-/Passwort-Reset-Versuche — relevant vor allem, falls das Dashboard über das eigene LAN hinaus erreichbar gemacht wird.

07Tech-Stack

Node.js + Express im Backend, Vanilla JS mit ES-Modulen im Frontend — bewusst ohne Build-Step. Die sf-api-Anbindung ist ein separater, zustandsloser Rust-Dienst, der nur auf 127.0.0.1 lauscht.
